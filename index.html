The engineering gap

Compiling is a milestone. Not a verdict.

AI can generate MQL5 code that compiles — and still fail under real execution, broker, state or risk conditions.

MQL5 Engineering adds an engineering layer around AI-assisted development. It encourages agents to inspect the actual project, consult authoritative documentation, challenge assumptions and validate critical paths before drawing conclusions.

No artificial confidence. Compilation, code review and backtests are not presented as proof of live-trading safety or profitability.

Six operating modes

One skill. The right workflow for the task.

Route the request to the narrowest workflow. Keep change implementation separate from review, product audit and release assessment.

01 / BUILD

Build

Create Expert Advisors, indicators, libraries, panels and integrations with deliberate architecture and validation seams.

02 / IMPROVE

Improve

Add features or refactor existing systems while protecting unrelated behavior and documenting the change.

03 / DEBUG

Debug

Reproduce symptoms, test hypotheses, find root causes, fix defects and verify regressions.

04 / REVIEW

Review

Assess a bounded change — branch, commit, pull request or diff — with evidence-backed findings.

05 / AUDIT

Audit

Run an adversarial product audit across applicable technical, execution, state, risk and operational domains.

06 / RELEASE

Release

Evaluate validation, compatibility, documentation and delivery readiness for a fixed product version.

Discovery-first engineering

Inspect first. Ask second.

The agent should discover facts already present in the repository, documentation, logs and configuration — and ask only when a real decision or missing external fact blocks safe progress.

Discover

Inspect source, structure, specs, presets, logs and available test feedback.

Route

Select BUILD, IMPROVE, DEBUG, REVIEW, AUDIT or RELEASE.

Engineer

Apply relevant workflows, auditors, invariants and scenarios.

Validate

Use the strongest practical test seam and state what was not tested.

Report

Deliver evidence, coverage, limitations and the appropriate readiness verdict.

Specialized audit passes

Independent review briefs help focus analysis on the risks that actually apply to the product.

  • Code correctness and MQL5 semantics
  • Trading logic, execution and state ownership
  • Financial risk and exposure
  • Indicators, Strategy Tester and time/session behavior
  • Economic Calendar, performance and UI
  • Licensing, security, documentation and MQL5 Market

Cross-cutting engineering controls

Reusable rules and failure scenarios strengthen consistency across different projects.

  • Engineering invariants for critical behavior
  • Adversarial scenarios for realistic failure modes
  • Broker and account-model compatibility reasoning
  • Evidence gates with severity and confidence
  • Validation levels from static inspection to demo forward
  • Explicit approval boundaries for source changes
Evidence over assumptions

Validation has levels.

Reports distinguish what was inspected, what was tested and what remains unverified. A higher level is not automatically required for every task; validation should match the risk and available environment.

READY

CONDITIONAL

BLOCKED

LIMITED COVERAGE

A material path could not be inspected or validated; a clean verdict is not justified.

Good to know

Frequently asked questions.

Understand what the skill does — and what it deliberately does not claim to do.

Is MQL5 Engineering an Expert Advisor or trading bot?

No. It is an open-source Agent Skill that guides compatible AI agents through MQL5 engineering workflows. It does not place trades or run a trading strategy by itself.

Does it guarantee safer or profitable trading systems?

No. It improves the engineering process by encouraging discovery, evidence and validation. It does not guarantee production safety, trading performance or profitability.

Which markets and instruments does it support?

The engineering approach is market-agnostic and can be applied to MT5 projects involving Forex, B3, metals such as XAUUSD, CFDs, indices and other instruments. Broker, symbol and account-model behavior must still be validated for each environment.

Which AI agents can use it?

The repository provides a reusable Agent Skill and installer targets for universal installation, OpenCode, Claude and project-local use. Runtime compatibility depends on the Agent Skills support provided by the environment.

Does compilation count as validation?

Compilation is Level 1: it confirms build or syntax validity. It does not establish correct trading behavior, execution quality, risk control, tester/live fidelity or release readiness.

Is the project open source?

Yes. MQL5 Engineering is released under the MIT License. You can inspect the source, use it, modify it and contribute through the public GitHub repository.
